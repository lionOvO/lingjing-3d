# 灵境造物：本地一键启动

在 `D:\灵境造物` 双击 `一键启动.bat`。脚本启动 Docker Desktop（未运行时），然后启动本目录的前端、后端、任务 worker 和 Compose 依赖。首次缺少应用镜像时会构建，可能需要联网并等待数分钟。需要已安装 Python 3、Docker Desktop，并配置项目根目录 `.env`。

前端优先使用 8080，后端优先使用 8000。端口被其他程序占用时向后寻找空闲端口，不关闭占用程序；端口发生竞争时最多重试三次。已运行的本目录服务会复用原端口。成功后自动打开前端，窗口显示本次实际地址和后端 API 文档地址。前端通过容器内 `api:8000` 代理请求，宿主机端口改变时无需修改前端配置。

当前机器通过 `local-stack.json` 登记原项目 `ai-3d-digital-human`，继续使用原账号、项目和模型数据。五个历史数据容器（MySQL、Redis、MinIO、Etcd、Milvus）按完整容器 ID、来源目录与服务名核验并复用；应用服务从 `D:\灵境造物` 的当前源码部署。登记的数据容器缺失时脚本报错，不创建空数据库。之前临时验证用的独立项目 `lingjing-12a65edbb2` 已停止，其数据卷仍保留。

双击 `一键停止.bat` 停止本目录项目，保留容器和数据卷。Docker 本身及其他项目不受影响。Docker 未运行时，停止脚本直接退出。

修改源码后，在 PowerShell 中运行以下命令重建应用镜像：

```powershell
cd D:\灵境造物
py -3 scripts/start_local.py --build
```

可选参数：

```powershell
py -3 scripts/start_local.py --frontend-port 8090 --api-port 8010
py -3 scripts/start_local.py --no-browser
py -3 scripts/start_local.py --stop
```

指定端口也是搜索起点；占用时仍会自动切换。若服务已经运行，会优先复用其现有端口。默认等待 Docker 引擎 120 秒、容器健康检查 300 秒，可通过 `--docker-timeout`、`--wait-timeout` 调整。构建和启动总等待上限为 30 分钟。

成功记录：`tmp/local-launcher/state.json`，包含实际访问地址、项目名和日志路径。启动日志：同目录 `start-日期-进程号.log`。启动失败时窗口会保留错误提示。

脚本不会修改 `.env`，也不输出其中的密钥。当前登记了宿主机 ComfyUI 的安装目录、嵌入式 Python 路径和输出目录：服务未运行时，隐藏启动低显存配置，只启用 ComfyUI-Trellis2-GGUF，并设置本机 Triton 编译器路径。已有 ComfyUI 服务会在输出目录一致时复用；不一致时明确报错，不强制关闭正在使用的引擎。停止脚本不关闭宿主机 ComfyUI，以免打断单独使用的工作流。启动成功会验证 API 身份、网页代理和生成能力接口；它不会自动提交耗时的 3D 任务。

如果 Docker 出现 `sailor-ingest.sock` 错误，请先退出错误窗口，从 Windows 开始菜单启动 Docker Desktop 后重试。无需为此点击“恢复出厂设置”。脚本也通过 Windows Explorer 尝试启动 Docker，以避开本次发现的启动环境问题。

## 2026-10-21：修复 E 盘输出目录挂载失败

截图对应日志 `tmp/local-launcher/start-20261021-203725-11592.log` 的首个错误是：

```text
error while creating mount source path '/run/desktop/mnt/host/e/.../ComfyUI/output':
mkdir /run/desktop/mnt/host/e: file exists
```

Windows 可以访问原目录，但 Docker Desktop 无法挂载该 E 盘路径，导致 Trellis 未启动、API 无法就绪；与前后端端口冲突无关。

本机的新输出链路固定为：

- `local-stack.json` 的 `comfyui.output_directory`：`D:\灵境造物\tmp\comfy-output`。
- 一键启动向 ComfyUI 传入 `--output-directory`，启动及复用时根据 `/system_stats` 的 `system.argv` 核对目录。
- `.env` 的 `TRELLIS_COMFY_HOST_OUTPUT_DIR=./tmp/comfy-output`。
- 容器内只读挂载 `/comfy-output`，`TRELLIS_COMFY_OUTPUT_DIR=/comfy-output`。

E 盘上的引擎、权重和历史输出保留；新生成的文件写入 D 盘。历史网页模型继续使用原数据库和对象存储。若手动启动了使用旧输出目录的 ComfyUI，一键启动会提示目录不一致；先等待任务完成，关闭该引擎，再运行一键启动。也可以手动启动时传入上述 `--output-directory`。脚本不会自动终止未知进程或正在生成的任务。

本次修复时确认队列为空，并核对启动记录中的 PID、Python 路径和命令行后，仅重启本项目登记的 ComfyUI。没有重置 Docker，没有删除容器数据卷，也没有重启其他项目。
