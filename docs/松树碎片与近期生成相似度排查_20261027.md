# 松树碎片与近期生成相似度排查

日期：2026-10-27。用户反馈首页松树与参考图相差很大，且近期生成模型相似度变差。

## 结论与当前完成范围

松树确实来自本机 Pixal3D-GGUF 引擎，不是程序拼装树假称模型生成。参考图由图像生成工具制作，3D 几何和旧纹理由本地模型生成；风摆是网页动画。**真实调用引擎不代表结果合格：旧松树的处理链路有明确错误。**

已修正首页素材生成脚本的网格重建顺序，并通过同参考图、同种子、同 512 精度的真实引擎运行验证树干、主枝和树冠重新连通。修正后的无纹理几何已保存。新纹理尚未完成，未替换首页资产，未修改平台通用工作流或引擎插件代码。不能将本次几何修复说成带纹理首页替换已完成，也不能说所有模型相似度已经解决。

## 松树根因

旧独立素材任务采用 `generate_texture_slat=False`，输出的是柔性双网格解码结果。插件 `Trellis2_GGUFPostProcessAndUnWrapAndRasterizer` 在 `mesh.attrs is None or mesh.coords is None` 时提前返回，只转换坐标；该分支不会执行其 remesh 开关。旧任务随后直接用 CuMesh 简化原始网格，产生大量重合重复面和碎片。

修正链路：生成节点 45 → 显式 `Trellis2ReconstructMeshWithQuad_GGUF` 节点 75 → 坐标转换 54 → 简化 70 → 后续纹理。重建保留浮动分支，不以删除小组件的方式伪装修复。旧流程原始导出已经破损，网页进一步简化只是放大了问题。

| 检查项 | 旧带纹理原始导出 | 修正后的几何 |
| --- | ---: | ---: |
| 三角面 | 178,029 | 170,368 |
| 顶点 | 4,024 | 84,995 |
| 重合重复三角面 | 146,088（约 82.1%） | 68（约 0.04%） |
| 最大连通主体表面积占比 | 约 25% | 99.48% |

重复面检查按坐标合并 UV 缝上的顶点，忽略三角面绕序；六位小数容差。这是几何完整性证据，不是像素相似度或身份相似度分数。修正几何仍有 248 条非流形边、4 个零面积面，未达到生产拓扑完美标准。

真实对照任务 `37336e9a-6cc0-4069-858c-ec3ba574b5e7`，成功，约 427.52 秒。种子 20261027，512 几何、16 步结构与 16 步形状、最大 tokens 24576、单视图。未通过提高采样精度来掩盖重建问题。

## 新纹理仍未通过

第一次带纹理完整链路任务 `d8d603d0-0e2f-4bad-89ac-db11c41b0d82` 在 NAF 条件特征复制到 CPU 时触发系统提交内存保护，提交内存约 47.67 / 47.69 GiB。该图还缓存了前序巨大解码网格。

随后在队列空闲时释放 ComfyUI 缓存，将已经验证的 GLB 直接加载为独立纹理任务，避免重新生成几何。任务 `a2782c78-7d27-41cb-ac73-ba649d51c936` 仍在 NAF 图像编码器拼接两个分支特征时发生 GPU OOM，尚未进入纹理采样导出。两次失败不是几何修复失败的证据；但说明新完整链路尚未跑通。

现有低显存路径已经包含 DINO → CPU 卸载，形状编码器也有卸载逻辑，不能再将此次 OOM 简单归因于漏写这个卸载。未降低纹理采样精度、未改参考图、未用照片投影替代模型纹理，也没有继续盲目重试。下一项需要单独测量纹理 NAF 编码阶段的实时分配及对象生命周期，再决定内存改造。执行时须先确认队列空闲，保留现有几何，成功后验证多角度外观再替换首页。
