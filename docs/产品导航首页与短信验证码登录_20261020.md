本文按实施顺序保留记录。当前注册行为以文末“手机号验证码注册”一节为准，已替换早期用户名、邮箱、密码直接注册的方式。

## 页面与入口

- `/` 为公开产品导航首页，使用现有月夜湖景、蓝灰工作面和宋体标题。首页包含图片生成、模型资产、模型对比、项目管理、生成预设、创作知识库的真实入口，以及任务入口和三步使用说明。右侧为二维到三维的创作示意，并标明不是实际模型结果。

- 未登录进入受保护页面时保留 `redirect`，登录后返回原页面；默认登录进入工作台。登录跳转拒绝协议相对地址、反斜杠和登录页循环。
- 登录保留密码、邮箱及原注册流程，新增“验证码登录”方式。注册仍为原用户名、邮箱、密码注册，不包含新增短信注册或找回密码。

## 账号与验证码规则

当前用户表没有独立手机号字段，验证码只登录 **用户名等于该手机号** 的现有账号；原账号 ID、密码和项目关联保持不变。非手机号用户名继续使用密码或邮箱登录；如需手机号绑定、短信注册，须另行实现绑定和验证流程。短信验证不会创建替代账号。

新增 API：

- `GET /api/v1/auth/options`：仅公开是否已配置、有效期与重发间隔，不返回密钥或模板内容。
- `POST /api/v1/auth/sms/send`：接收 `phone`。
- `POST /api/v1/auth/login/phone`：接收 `phone` 和 `code`，成功后签发与密码登录相同的令牌，由 `/auth/me` 恢复账号。

Redis 使用独立 `lingjing:sms:v1` 前缀，手机号/IP 经 HMAC 转为键名。Lua 脚本保证发送预留、次数限制、验证码校验占用与消费在多个 API 进程间原子执行：每号 60 秒一次、每小时 5 次、每日 20 次；连接 IP 每 10 分钟 10 次；单次发送最多尝试校验 5 次。成功校验后删除挑战，阻止重放。供应商故障也计入尝试并保留重发冷却，不自动重发付费短信。没有本地万能验证码或客户端返回验证码。

未注册号码不会发送短信，接口使用相同通用提示，降低账号枚举风险。错误响应不透传供应商消息。Redis 故障时拒绝验证码登录，并提示使用密码方式。

IP 限流使用实际连接地址，不信任客户端自带转发头。目前 Nginx 后的用户共享此 IP 配额；若未来正式开放多人使用，需按受信代理链配置客户端 IP 解析，再调整 IP 配额，不能直接信任任意请求头。

## 同日补充：手机号验证码注册

根据用户要求，将注册接入现有阿里云 PNVS 短信流程，沿用浅蓝表单与双栏布局。新账号使用手机号作为用户名，不修改已有账号。

页面分两步：第一步填写手机号和 6 位短信验证码；第二步填写邮箱并设置 8–128 位密码，可返回修改手机号。第一步只检查输入格式并进入账号设置，**不将格式检查冒充短信验证**；页面明确提示提交“验证并创建账号”时由服务端校验短信。邮箱继续作为必填、唯一的联系方式及密码登录标识，本次不新增邮箱验证码验证。注册成功后回到密码登录并填入手机号，不自动登录，也不重复使用刚消费的注册验证码。

`POST /api/v1/auth/sms/send` 新增 `purpose`，取值 `login` 或 `register`，缺省保持 `login` 兼容原登录客户端。登录仍只对已有手机号账号发送；注册对新手机号发送，手机号已存在返回冲突提示。手机号、小时/每日/IP 发送配额与 60 秒冷却在两种用途间共享，不能切换用途绕过。

`POST /api/v1/auth/register` 现在强制要求 `phone`、`code`、`email`、`password`（可选原头像字段）；废弃不带验证码的用户名注册请求。Redis 挑战记录加入用途，服务端验证前检查用途与尝试次数；注册和登录验证码不可互换。成功验证后原子消费挑战，密码只保存哈希；数据库唯一约束及冲突处理防止并发创建重复账号。改版前已发送但没有用途标记的验证码需要重新获取。

早期 `POST /api/v1/users` 能接收客户端密码哈希直接创建用户，会绕过短信注册，因此现已关闭，合法请求返回 410 并提示通过手机号验证码注册。测试改为直接向隔离数据库写入历史账号测试夹具；原有账号、密码、项目和模型数据保持不变。历史用户名/邮箱密码登录及刷新令牌继续通过回归测试。
