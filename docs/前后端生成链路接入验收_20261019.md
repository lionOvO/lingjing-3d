## 发现及修复

1. 原 8080 环境 Trellis 容器引用旧目录的文件挂载，无法启动。已将五个应用服务接到当前目录源码，继续使用原五个数据容器。新增 `docker-compose.local.yml` 和 `local-stack.json`，明确核验历史数据容器 ID、所属目录与服务名，缺失时停止启动。
2. 原页面提示远程 Hugging Face、默认 2048px，与真实本机提供方不符。新增生成能力接口，由实际就绪的适配器决定可用模式，默认改为高质量、1024px、中面数、PBR。
3. 云端文字属性分析订阅不可用。当前本机覆盖配置允许高质量任务跳过该可选步骤，保留参考图与用户所选参数；明确记录 `analysis_skipped`，不编造角色属性，不调用依赖该描述的语义检索。严格失败模式仍保留为配置默认值。
4. 透明 PNG 被重复送入较大的 BRIA 抠图模型，出现 ONNX bad allocation。现在保留已有 alpha；普通 JPG/不透明图先在独立 CPU 子进程中使用已缓存的 U2Net 抠图，进程退出释放其内存后才提交 ComfyUI，节点 55 关闭重复抠图。普通 JPG 抠图独立实测约 10.3 秒，本次完整网页任务也覆盖了此路径。
5. 同时运行网页依赖后，MoGe 构造模型时触发 Windows 原生访问异常。安装的 MoGe 加载改为 mmap 读取 checkpoint、accelerate 空参数初始化和 assign=True，避免同时保留完整随机初始化权重和 checkpoint 副本，保留实际小缓冲区并检查未加载的 meta 张量。单独加载 326,209,221 个参数成功，随后完整任务通过。安装脚本：`scripts/patch_moge_loading.py`；原文件备份在安装目录的 `v2.py.before-lingjing-mmap-20261019`。插件升级覆盖文件后需重新核对并应用修复。
6. 一键启动现在可在 ComfyUI 未运行时，以已验证的低显存、仅启用 GGUF 插件配置隐藏启动它，并设置本机 Triton 编译器路径。启动完成会检查网页生成能力，避免只报告网页和 API 已启动。已有服务会复用；停止网页脚本不关闭独立使用的 ComfyUI。
7. Nginx 改用 Docker DNS 动态解析 API，保留 Host 中的端口；后端重建后无需因旧 IP 重启前端。下载和预览 URL 在前端归一为同源路径，下载改用直接链接，已实际点击并核对文件哈希。
8. 预览器原先切到实体/线框后会清掉基础色贴图且无法恢复。现在保存原材质，切回材质模式恢复原贴图与颜色；材质倍率默认 1，保留模型本身的 PBR 值。实际模型已验证实体显示与材质恢复。
9. 补齐后端读取 GLB 贴图所需的 Pillow 依赖。未来任务在检查网格时记录实际顶点数、大小与边界；较早缺少计数的记录从实际 GLB 补充响应统计，避免页面显示无数据或预设数。
10. 适配器及后端保留实际节点错误，已报告推理失败的请求不会作为网络错误重复提交 GPU 任务。网络重试在本机覆盖配置中为 0，适配器超时 3300 秒，后端 3600 秒。
