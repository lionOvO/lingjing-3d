# 引擎下载与复现说明

核对日期：2026-10-27。当前应用使用 ComfyUI + Aero-Ex 的 Trellis2/Pixal3D GGUF 节点，工作流加载 `Pixal3D-GGUF`。Trimesh 是网格检查/处理库，不是这里的大模型引擎。

## 安装目录为什么这么大

本机扫描的安装目录为 63,968,481,876 字节（约 64.0 GB / 59.6 GiB），其中 Python 及依赖约 12.0 GB。目录还包含 Q4、Q8 两套量化权重、其他图片生成模型、备份、历史产物与缓存。无需将整个安装目录上传 Git。未扫描 E 盘其他无关目录，也未删除任何权重。

此清单不是全环境大小：Q4 核心 HF 文件约 8.38 GB，Q8 约 11.13 GB，两套是替代方案；另需项目抠图模型约 352 MB、NAF 检查点约 2.7 MB、NAF 源码以及 Python/CUDA 原生依赖。下载缓存、构建和复制过程还需要额外磁盘空间。

## 保留本机修改，避免下载后行为不同

引擎节点在本机有 14 个已跟踪文件的修改和 2 个新增源码文件；当前结果不能仅靠下载上游最新版本复现。完整差异保存为 [本地引擎补丁](../engine/patches/pixal3d-local-20261027.patch)，以记录的节点提交为基线；补丁包含 NAF、内存生命周期、GGUF 加载、网格处理等实际修改，并保留上游许可。

在独立的新节点 checkout 中执行，不能直接覆盖正在使用的 E 盘引擎：

```powershell
git clone https://github.com/Aero-Ex/ComfyUI-Trellis2-GGUF.git ComfyUI-Trellis2-GGUF
cd ComfyUI-Trellis2-GGUF
git checkout b3b9e951874c5fb5c936566c93b908299be08b2c
git apply --check "<项目目录>/engine/patches/pixal3d-local-20261027.patch"
git apply "<项目目录>/engine/patches/pixal3d-local-20261027.patch"
```

应用层工作流为 `services/trellis/workflow_6gb.json`；它的加载器配置为 Q4，但生成参数也可能由适配器调整，文件名 `6gb` 不是峰值显存保证。网页会按当前质量档位调整参数。低显存模式、内存/页面文件、输入复杂度、纹理分辨率都会影响运行；没有承诺任意图片在 6 GB 显存上成功。

下载说明中的必需文件不包括 Z-Image Turbo、Qwen 文生图文本编码器、视频插件、历史备份等本项目当前 3D 主链路未用内容。这里只做来源调查，没有下载新的大型权重，也没有清理本机文件。

## CuMesh 安装包内的额外修复

本机 `cumesh/remeshing.py` 还应用了 [显存生命周期补丁](../engine/patches/cumesh-memory-20261023.patch)，原先记录见 [修复文档](CuMesh重建显存修复_20261023.md)。补丁以本机安装包为基线，不属于上面的节点 Git 补丁；修改前后的 SHA256 已存 `engine/versions.json`。重新安装 CuMesh 后应先检查基线和补丁上下文，不能对任意新版盲目套用。
