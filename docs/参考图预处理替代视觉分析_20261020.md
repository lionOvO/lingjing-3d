# 参考图预处理替代生成前的视觉语言分析

日期：2026-10-20。项目：D:\灵境造物。

> 后续更新：本文件记录第一版。用户随后明确要求以“人物更适合 3D 重建”为目标，而不是默认白底/透明底。当前默认行为以 [人物参考图保真预处理优化_20261020.md](人物参考图保真预处理优化_20261020.md) 为准：保留人物与背景、整理构图，去背景改为可选；下文“进入第二步自动抠图”已被替代。

## 用户目标与设计

将工作流第二步“理解与标准化”调整为“参考图预处理”，让白底或透明底图片真正作为生成输入，而非仅在生成已经开始后展示分析页。当前本机 Pixal3D 自身通过图像条件编码重建模型，独立视觉语言模型不再是新任务的前置服务。以后可将其作为输入质量提示、参数建议或多视图外观复核的可选能力，不能据此承诺模型外观必然更好。

新任务流程：上传与配置 → 参考图预处理 → 确认并开始生成 3D → 生成与质检 → 预览与交付。第二步确认前，不创建项目、任务或 GPU 队列项；CPU 抠图不会启动 3D 推理。

## 前端行为

- 进入第二步自动调用已有的本机 CPU U2Net 抠图接口。已有透明 PNG 保留原有 alpha。
- 提供透明底、白底两种 PNG 输出，统一 1024×1024；支持裁剪、主体居中与 0–24% 留白。
- 保留未经处理的原图对照。必须点击“确认此图用于生成”，最终生成按钮才可用；改底色、裁剪或留白使旧确认失效。
- 抠图误删头发、手臂、披风或配饰时，可选择“保留原图用于生成”；该分支保留原始图片尺寸，不会在后台再次自动抠图。
- 未成功去背景且没有有效 alpha 的处理结果，不能在新流程中被确认为白底/透明底。可恢复、重试或明确选择原图。
- 返回上传与配置时保留当前图片与参数。刷新页面不持久化浏览器内的 File；第二步会提示重新选择图片。
- 生成服务离线时可先整理图片，提交生成前重新检查服务。
- 历史任务的第二步仅查看原图/输入记录，不修改已经排队的任务；旧任务没有独立原图快照时明确说明。

## 后端与 ComfyUI 链路

1. 新增登录保护的 `POST /api/v1/studio/images/import-url`，复用现有上传 URL 校验，返回图片供浏览器处理并清理临时对象；不创建任务。
2. 新增登录及任务所有权保护的 `GET /api/v1/studio/tasks/{id}/input`；`original=true` 读取独立原图。支持未完成任务。没有历史快照的实际输入只可回退为项目当前参考图，并用 `X-Input-Kind: project_current` 标明。
3. 提交时分别保存原图与确认后的图片。任务记录 `_original_source_object_name`、现有 `_source_object_name` 及 `image_preparation`（版本、底色、抠图、裁剪、留白等）。对象路径不写到公开案例中。
4. 新任务设置 `input_preprocessed=true`、`vision_analysis=false`。分析 Agent 不调用视觉语言 HTTP 服务，不凭空识别角色属性；RAG 沿用已有 image-only 跳过策略，保留用户所选纹理、面数与 PBR 参数。
5. 本机适配器跳过 `_prepare_comfy_input` 自动分割。确认后的图片只做确定性的 RGB 条件转换：透明像素合成到既有链路使用的黑底，白底保持白色，EXIF 方向归一化；不裁剪、不改变画布尺寸。MinIO 中保留的确认 PNG 不变。
6. 对确认输入，将 ComfyUI 节点 55 的 `remove_background=false`、`padding=0`。输入先转为 RGB，避免原节点基于 alpha 包围盒再次裁剪，从而保留浏览器确认的构图和留白。旧任务保持其原有处理分支。
7. 任务页按实际情况显示“输入确认”“参数准备”，不把跳过视觉模型显示为已提取特征。任务参考图读取任务快照。

## 验证

- 前端 Vite 生产构建通过。既有大包体积提示仍在，不影响构建。
- 后端 50 项相关测试通过，覆盖创建任务、Agent、生成参数、上传、结构工具与所有权校验；其中新增测试验证：确认输入入队与冻结路径、原图和处理图分别读取、预处理不入队、URL 临时对象清理、不调用视觉语言 HTTP 服务、参数传给生成器。
- 生成适配器 18 项测试通过，新增白底输入不再分割、ComfyUI 不重复留白、透明输入 RGB 转换保持尺寸及原文件字节不变。ComfyUI 的 HTTP 与 GLB 回传在该测试中使用受控替身，不冒充新增 GPU 生成。
- 浏览器使用账号已有的 1024×1024 参考图进入新流程，实际抠图、透明/白底切换、确认按钮启用、底色变更后确认失效、返回后原图与参数保留均已检查。
- 验收时发现宿主机 ComfyUI 未监听 8188，已通过项目现有 `local_comfy.ensure_comfy` 低显存启动配置恢复；生成能力接口重新返回本机 Pixal3D / high_quality / 1024、2048。更新服务前检查 Celery active 为空。
- 本轮没有新增完整 GPU 3D 推理，不能把接口及受控队列测试等同于新生成模型的外观提升证明。

## 边界

U2Net 可能误删复杂服装和细部，保留原图对照及明确确认不可省略。图片放大到 1024 不会恢复缺失信息；白底/透明底也不能恢复背面、修正五官或替代生成器能力。当前变更针对项目的本机 ComfyUI 提供方，未宣称远程提供方遵守同样的构图约定。
