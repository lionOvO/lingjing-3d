# Pixal3D：NAF 编码阶段显存修复

## 故障与定位

网页项目 28、任务 33 在 2026-10-21 首次生成失败。ComfyUI prompt 为 `f602e816-2914-44c4-9558-f05b72a1d38b`，约 520 秒后在节点 45 抛出 `torch.OutOfMemoryError`。

调用链为 `sample_shape_slat_cascade → get_proj_cond_shape → _proj_naf_tiled → image_encoder.forward_encoder → torch.cat([encoder(x), sem_encoder(x)])`。失败在高分辨率形状条件重建阶段，尚未进入纹理导出。截图中的 batch_size 提示是 ComfyUI 的通用报错；实际输入批次为 1。

机器为 RTX 3060 Laptop 6GB。工作流已启用 Q4_K_M、low_vram、NAF K4 和分块解码，但 NAF 编码完整引导图时，已提取完特征的 DINO 模型仍留在 GPU。它与 NAF 编码器的两个分支、拼接结果和当前阶段的条件张量同时占用显存。

## 修改

只修改已安装插件的 `trellis2_gguf/pipelines/trellis2_image_to_3d.py`：在 `project_sparse_features` 中，先完成 DINO 特征提取并初始化 NAF，再在 `low_vram` 模式下将 DINO 子模型移到 CPU，清理 CUDA 缓存，随后运行原来的 NAF 编码与投影。

必须先初始化 NAF，因为懒加载器根据 DINO 参数所在设备确定 NAF 的设备。提前卸载到 CPU 会导致 NAF 被错误加载到 CPU。

采样种子、步数、1024_cascade、NAF K4、权重类型、相机估计、纹理分辨率、后处理和面数设置均保留。没有重新抠图或重绘参考图。

安装工具：`scripts/patch_pixal_naf_encoder_offload_20261021.py`。它核验源文件哈希、要求先停止引擎、保留备份，并输出差异文件 `docs/Pixal3D_NAF编码显存修复_20261021.patch`。修改前源码 SHA-256 为 `136d5aae6462d78d987367526b4733afeb4ce5b70a25da6c9c289a871b62f359`，修改后为 `b29b925934d6f410b8d755809c89a1ccce2c009a2b1b63774f382acc8af09d79`。

备份位于原源码同目录，后缀为 `.bak-before-naf-encoder-offload-20261021`。回滚也必须先等待任务完成并停止 ComfyUI，再恢复备份，随后重新启动。插件升级后需要重新核对补丁，不应绕过哈希保护强行安装。
