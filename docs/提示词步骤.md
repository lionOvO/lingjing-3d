你应该用 **Codex 提示词文件** 作为主文件去喂，PRD 文档作为**参考/验收标准**放在旁边查。原因是：

- **Codex 提示词** = 技术实现说明书（含代码架构、API、Schema、智能体代码），Codex 能直接翻译成代码
- **PRD 文档** = 业务需求书（含市场分析、用户画像、流程图），Codex 看了会"懂业务但不知道怎么写代码"

------

## 给 Codex 的实战操作指南

### 第一步：先让 Codex 生成项目骨架（第 1 轮对话）

把 Codex 提示词文件的 **「二、技术栈」到「三、系统架构」** 部分复制进去，加上这句：

## 关键技巧

| 技巧                | 说明                                                         |
| :------------------ | :----------------------------------------------------------- |
| **分模块给**        | 不要一次性把 2000 行全贴进去，Codex 上下文有限，容易"失忆"   |
| **先给 Schema**     | 数据库表结构是最稳定的契约，先定好 Schema 再生成 API 和前端  |
| **要求给测试**      | 每轮都加一句"包含 pytest 单元测试"，否则 Codex 容易漏        |
| **用 `@file` 引用** | 如果 Codex 支持（如 Cursor），用 `@` 引用已生成的文件作为上下文 |
| **PRD 当检查单**    | 生成完一个模块后，对照 PRD 的「验收标准」让 Codex 自查补漏   |

------

**总结**：拿着 **Codex 提示词文件** 去喂，按「骨架 → 后端模块 → 前端页面 → 联调」四步走，PRD 放在手边当验收 checklist。需要我把 Codex 提示词文件按"可分批投喂"的方式重新拆分成几个小文件吗？
