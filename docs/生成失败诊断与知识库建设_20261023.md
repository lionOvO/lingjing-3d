# 生成失败诊断与知识库建设（2026-10-23）

## 本次定位

将知识检索用于失败后的定位与建议，独立于图片预处理、Pixal3D 推理和确定性质量检查。页面入口在失败任务的“生成与质检”中，标题为“先查原因，再决定重试”。创作知识库默认展示“生成故障”分类，可以搜索、分页和查看资料来源。

第一版采用**错误分类 + 工作流适用条件过滤 + 版本化知识条目 + 有依据的固定解释**。不调用语言模型，不使用哈希占位向量，不展示虚构相似度；它是可核查的知识检索诊断，还不是由语言模型综合日志的完整 RAG。已有 Milvus 数据与 Blender 知识不参与本次故障建议。

## 检测内容与边界

- 失败时：读取该任务持久化的错误、引擎与提供方、种子、纹理和面数等参数。这个错误是任务保存的片段，不等于完整宿主机日志。
- 当前：通过内部适配器读取 ComfyUI `/system_stats`、`/queue`，只返回在线状态、物理内存、显存、队列计数及当前工作流指纹。工作流检查只核对必要节点，不代表插件补丁、模型文件与运行结果全部正确。
- 显示时间明确区分失败记录与当前检测。当前内存充足不能证明失败时充足，当前在线不能证明原任务成功。整个引擎的队列数量不能关联到具体任务。
- 不读取 Windows 控制台文件、系统提交额度、分页文件或磁盘容量。缺少这些数据时明确标注未知，不把任意断连归因于内存。
- 接口要求登录并按项目归属验证任务；其他用户返回 404，在验证归属前不探测基础设施。
- 只诊断失败任务；诊断期间若发生重试或状态变化，返回 409，避免将旧错误当成新一轮任务的诊断。
- 没有命中时明确说明，保留人工核查路径。不自动执行命令、改参数、安装补丁或重新提交 GPU 任务。
- 整个报告可以导出 JSON，包含知识版本和检测时间。报告中的错误地址、Bearer、常见密钥字段进行脱敏。

接口：

- `GET /api/v1/studio/tasks/{task_id}/diagnosis`
- `GET /api/v1/studio/diagnosis/knowledge`
- 内部适配器 `GET /diagnostics`，不暴露提示词、队列任务内容、启动参数或原始日志。

本机滚动更新时，若旧适配器尚无 `/diagnostics`（404），可通过本地 Compose 明确配置的 `DIAGNOSTICS_COMFY_URL` 只读访问 ComfyUI 统计与队列；不从任务文本猜地址，不中断正在执行的生成。远程提供方不执行本机检测。宿主机探测失败只标为离线或未知，不生成虚构内存值。

## 接下来真正需要补充什么

### 优先：本项目真实故障与修复案例

每个案例应保存：

1. 失败任务和尝试编号、时间、失败阶段／节点、脱敏后的原始异常。
2. 引擎、插件、模型和工作流版本／指纹，以及补丁是否安装。当前诊断只知道当前工作流指纹，无法还原旧任务运行时版本。
3. 输入类别与构图特征、实际生成参数、显卡与显存。图片对象地址不作为公开知识内容。
4. 失败时的 GPU 峰值、可用物理内存、Windows 已提交当前值与上限。磁盘空闲量单独记录，不冒充内存值。
5. 实际实施了什么修改，是否保留原参数；没有执行的建议不能算作修复。
6. 修改后的验证：引擎执行、有效 GLB、纹理、平台下载、外观人工验收分别记录。
7. 未解决部分、反例、适用版本、回滚方法。一次成功不能宣称普遍有效。

优先回填 #33 的 NAF 显存案例、#36 的系统提交案例，以及之后遇到的真实失败。任务重试可能覆盖旧错误，后续应在 worker 增加独立的“每次尝试事件”记录，才能形成长期案例库。本次没有为了演示制造失败任务或自动修改历史数据。

### 优先：运行与兼容性知识

- 当前 Pixal3D 工作流实际支持的参数；1024 验证范围、2048 实验风险。
- Windows 原生引擎与 Docker 适配器的地址、输出目录映射、启动与就绪检查规则。
- 不同工作流／插件／模型版本的兼容表与缺失资源清单。
- 明确说明来源、发布日期和版本的官方安装／错误处理文档。

### 之后：预处理、修复与交付知识

- 人物、建筑、细长物体等不同输入的完整性检查与已验证分割策略。
- 背景被重建、部位缺失、脸部失真、纹理错位的正反例；区分输入、几何与纹理问题。
- 拓扑检查可做和不可做的修复；带 UV、骨骼、动画时的限制。
- GLB、纹理、文件保存、下载失败的定位步骤。

失败的面部投影和头部重建试验可以作为“不应推荐的反例”，不能标记为已经验证的解决办法。

## 维护规则

新增条目至少包含 `id`、`codes`、`title`、`content`、`applicability`、`verification`、`actions` 和 `sources`；修改知识时升级文件顶层版本。源文件受版本控制，发布时随后端打包。当前页面是只读浏览，不支持任意用户编辑诊断规则。

若将来接语言模型解释报告，只提供脱敏后的任务证据和已过滤知识；建议必须能对应条目来源，未知项不得编造。语义向量检索仅在知识规模和表述复杂度值得时增加，入库与查询必须使用同一个真实 embedding 模型。实时资源状态始终来自检测工具。
