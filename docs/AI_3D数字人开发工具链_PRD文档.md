## 一、文档概述

### 1.1 文档目的

本文档为 **AI 3D 数字人开发工具链** 的产品需求文档（Product Requirements Document，PRD），旨在明确产品的业务目标、功能范围、用户场景、交互逻辑、数据需求及验收标准，为产品设计、开发、测试、运营团队提供统一的需求基准与协作依据。

### 1.2 适用范围

本文档适用于以下角色：

| 角色 | 使用场景 |
|------|---------|
| 产品经理 | 需求评审、迭代规划、功能优先级排序 |
| UI/UX 设计师 | 页面原型设计、交互流程设计、视觉规范制定 |
| 前端工程师 | 页面实现、组件开发、交互逻辑编码 |
| 后端工程师 | API 设计、数据库设计、服务架构实现 |
| 算法工程师 | 3D 生成模型集成、智能体工作流开发、RAG 系统构建 |
| 测试工程师 | 测试用例设计、验收测试执行 |
| 运营人员 | 用户反馈收集、功能推广、数据监控 |

### 1.3 术语表

| 术语 | 英文全称 | 定义 |
|------|---------|------|
| RAG | Retrieval-Augmented Generation | 检索增强生成，通过检索外部知识库增强大模型生成能力的技术 |
| PBR | Physically Based Rendering | 基于物理的渲染，模拟真实光照与材质反射的渲染技术 |
| GLB | GL Transmission Format Binary | 一种高效的 3D 模型二进制格式，支持材质、动画、场景 |
| Mesh | 网格 | 由顶点、边、面组成的 3D 几何体数据结构 |
| 智能体 | Agent | 能够自主感知环境、做出决策并执行动作的 AI 实体 |
| LangGraph | - | LangChain 框架下的图结构工作流编排工具，用于构建多智能体状态机 |
| DeepAgents | - | 基于深度学习的智能体框架，支持复杂任务分解与协作 |
| Embedding | 嵌入向量 | 将文本/图像/数据映射到高维向量空间的技术表示 |
| Milvus | - | 开源向量数据库，专为 AI 和向量相似度检索设计 |
| Celery | - | Python 分布式任务队列，用于异步任务调度与执行 |
| WebSocket | - | 全双工通信协议，支持服务器向客户端实时推送数据 |
| 水密性 | Watertight | 3D 模型表面无孔洞、无缝隙，可完全封闭的几何特性 |
| 流形性 | Manifold | 3D 网格每个边恰好属于两个面，无自相交的几何特性 |

## 二、产品概述

### 2.1 产品背景

#### 2.1.1 行业背景

随着 AIGC（人工智能生成内容）技术的爆发式发展，3D 内容创作正经历从「专业工具驱动」向「AI 智能驱动」的范式转变。传统 3D 建模流程（概念设计 → 高模雕刻 → 拓扑优化 → UV 展开 → 材质贴图 → 骨骼绑定）通常需要数天至数周，且严重依赖专业美术人员的技术积累。

2024-2026 年间，以 TRELLIS、Hunyuan3D、TripoSR 为代表的开源图片转 3D 模型技术取得突破性进展，单张图片生成高质量 3D 模型的时间从数小时缩短至数秒，生成质量已达到游戏资产和虚拟偶像制作的可用标准。与此同时，多模态大模型（如 Qwen2-VL、InternVL2）在视觉理解方面的能力显著提升，使得 AI 能够精准识别动漫角色的发型、服装、配饰、姿态等细粒度特征。

#### 2.1.2 市场痛点

当前市场存在以下核心痛点：

| 痛点 | 现状描述 | 影响对象 |
|------|---------|---------|
| **建模门槛高** | 3D 建模需要掌握 Blender/Maya/ZBrush 等专业软件，学习曲线陡峭 | 独立开发者、小型团队 |
| **制作周期长** | 一个高质量角色模型从设计到完成通常需要 3-7 个工作日 | 游戏公司、动画工作室 |
| **成本高昂** | 专业 3D 美术师人力成本高（月薪 15K-50K），外包单件角色模型 500-5000 元 | 中小型企业、个人创作者 |
| **风格一致性差** | 现有通用 3D 生成工具对动漫/二次元风格的理解和还原能力不足 | 虚拟偶像运营者、二次元游戏开发者 |
| **参数调优困难** | 3D 生成涉及大量超参数（面数、纹理分辨率、拓扑类型等），非专业人员难以选择最优组合 | 所有用户 |
| **缺乏知识沉淀** | 每次生成都是独立过程，无法从历史成功案例中学习和优化 | 平台运营方、高级用户 |

#### 2.1.3 技术机遇

1. **图片转 3D 技术成熟**：TRELLIS-2 在 2025 年实现了 4B 参数规模下的 ~3 秒高质量生成，支持 GLB/OBJ/PLY 多格式输出，动漫角色生成效果达到商用级别。
2. **多模态视觉理解突破**：Qwen2-VL-72B 能够精准识别动漫角色的发型颜色、服装款式、配饰细节、表情姿态，为风格化 3D 生成提供结构化输入。
3. **智能体技术成熟**：LangGraph + DeepAgents 支持构建复杂的多智能体协作工作流，实现「分析 → 检索 → 生成 → 评估 → 优化」的闭环自动化。
4. **RAG 技术普及**：Milvus 向量数据库支持亿级向量毫秒级检索，使得基于历史生成数据的知识沉淀和参数推荐成为可能。

### 2.2 产品目标

#### 2.2.1 愿景

> 让每个人都能在 30 秒内，将一张动漫图片转化为可用于游戏、虚拟直播、3D 打印的专业级 3D 数字人。

#### 2.2.2 核心目标

| 目标维度 | 具体目标 | 衡量指标 |
|---------|---------|---------|
| **效率提升** | 将动漫角色 3D 化时间从数天缩短至 3 分钟以内 | 端到端生成耗时 < 180 秒 |
| **质量达标** | 生成模型达到游戏资产和虚拟偶像制作的可用标准 | 质量评分 >= 0.8 的通过率 >= 90% |
| **降低门槛** | 零 3D 建模经验的用户也能独立完成角色 3D 化 | 新用户首次成功生成率 >= 85% |
| **风格精准** | 动漫风格还原度达到用户可接受水平 | 风格匹配满意度 >= 4.0/5.0 |
| **知识沉淀** | 通过 RAG 系统持续积累生成经验，提升后续生成质量 | 参数推荐采纳率 >= 70% |
| **生态扩展** | 支持物品 3D 建模，覆盖更广泛的 3D 内容创作场景 | 物品建模成功率 >= 85% |

#### 2.2.3 成功指标（OKR）

**O1：成为动漫角色 3D 化领域的首选工具**

- KR1.1：上线 3 个月内，月活跃用户数（MAU）达到 10,000+
- KR1.2：用户平均每周生成次数 >= 5 次
- KR1.3：NPS（净推荐值）>= 40

**O2：建立行业领先的 AI + RAG 3D 生成技术壁垒**

- KR2.1：RAG 知识库覆盖 >= 1000 条高质量生成参数记录
- KR2.2：参数推荐使生成成功率提升 >= 15%
- KR2.3：智能体工作流自动化率达到 >= 95%

**O3：实现可持续的商业模式**

- KR3.1：上线 6 个月内，付费转化率达到 5%
- KR3.2：企业客户（游戏公司/虚拟偶像机构）签约 >= 20 家
- KR3.3：API 调用量月均增长 >= 30%

### 2.3 产品定位

#### 2.3.1 一句话定位

> **AI 驱动的 3D 数字人一站式开发平台，让图片秒变 3D，让创意即刻立体。**

#### 2.3.2 产品定位矩阵

```
                    高专业度
                       ↑
    ┌──────────────────┼──────────────────┐
    │   Blender/Maya   │  专业 3D 工作室   │
    │   (专业工具)     │  (定制服务)       │
    │                  │                   │
低效率←────────────────┼────────────────→高效率
    │                  │   ★ 本产品 ★     │
    │   传统外包       │  (AI 智能平台)    │
    │   (人工服务)     │                   │
    └──────────────────┼──────────────────┘
                       ↓
                    低专业度
```

**定位说明**：本产品处于「高效率 + 中高专业度」象限，介于专业 3D 工具和传统外包之间，通过 AI 自动化大幅降低 3D 建模门槛，同时保证输出质量达到专业可用标准。

#### 2.3.3 目标用户分层

| 用户层级 | 占比（预估） | 核心诉求 | 付费意愿 |
|---------|------------|---------|---------|
| **核心用户** | 40% | 快速将动漫角色 3D 化，用于虚拟直播、游戏开发 | 高（订阅制/按量付费） |
| **扩展用户** | 35% | 物品 3D 建模，用于 3D 打印、电商展示、AR 应用 | 中（按量付费） |
| **潜在用户** | 25% | 探索 AI 3D 生成能力，学习 3D 内容创作 | 低（免费版） |

## 三、市场与竞品分析

### 3.1 市场规模

#### 3.1.1 全球 3D 内容市场

根据 Grand View Research 2025 年报告，全球 3D 内容创作市场规模预计：

| 年份 | 市场规模 | 年增长率 |
|------|---------|---------|
| 2024 | 158 亿美元 | 18.2% |
| 2025 | 187 亿美元 | 18.4% |
| 2026（预测）| 221 亿美元 | 18.2% |
| 2028（预测）| 310 亿美元 | 17.8% |
| 2030（预测）| 430 亿美元 | 16.9% |

其中，AI 驱动的 3D 生成细分市场增速最快，2024-2030 年复合增长率（CAGR）预计达到 **45.3%**。

#### 3.1.2 中国 3D 内容市场

中国作为全球第二大游戏市场和最大的虚拟偶像市场，3D 内容需求旺盛：

- **游戏行业**：2025 年中国游戏市场实际销售收入 3,200+ 亿元，其中 3D 游戏占比超过 70%
- **虚拟偶像**：2025 年中国虚拟偶像核心产业规模突破 200 亿元，虚拟主播/VTuber 数量超过 50 万
- **3D 打印**：2025 年中国 3D 打印市场规模达到 380 亿元，消费级 3D 打印用户超过 300 万
- **二次元经济**：中国泛二次元用户规模 5.2 亿，核心二次元用户 1.2 亿

#### 3.2.4 差异化竞争优势

1. **动漫角色深度理解**：通过多模态 AI 智能体精准识别角色特征（发型、服装、配饰、姿态），实现风格化 3D 生成的精准还原，这是现有竞品均不具备的能力。
2. **RAG 驱动的参数智能推荐**：基于历史生成数据和风格知识库，自动推荐最优生成参数，降低用户调参门槛，持续优化生成质量。
3. **多智能体协作工作流**：LangGraph 编排的「分析 → 检索 → 生成 → 评估 → 优化」闭环，实现全流程自动化，减少人工干预。
4. **质量评估与自动重试**：内置 Mesh 质量检查智能体，自动识别水密性、流形性等问题并触发参数调优重试，保证输出质量。
5. **开源技术栈**：基于 TRELLIS-2、TripoSR 等开源方案，避免对闭源 API 的依赖，支持私有化部署，满足企业客户的合规需求。

#### 5.1.2 数据流架构

```

    │
    ▼

    │
    ▼
[FastAPI] 接收上传 → 存入 MinIO → 生成 task_id
    │
    ▼
[Celery] 异步任务入队
    │
    ▼
[LangGraph] MasterAgent 启动工作流
    │
    ├──→ [CharacterAnalysisAgent] 调用 Qwen2-VL 分析图片
    │       │
    │       ▼
    │       输出角色特征 JSON → 存入 MySQL
    │       特征 Embedding → 存入 Milvus
    │
    ├──→ [RAGRetrievalAgent] Milvus 向量检索
    │       │
    │       ▼
    │       检索相似风格/参数/材质 → 融合排序
    │       输出优化后的 generation_params
    │
    ├──→ [ModelGenerationAgent] 调用 3D 生成引擎
    │       │
    │       ├──→ TRELLIS-2（高质量模式）
    │       └──→ TripoSR（快速预览模式）
    │       │
    │       ▼
    │       生成 3D 模型 + 纹理贴图 → 存入 MinIO
    │
    ├──→ [QualityCheckAgent] Mesh 质量评估
    │       │
    │       ├──→ 通过 → 进入后处理
    │       └──→ 不通过 → 参数调优 → 回到生成（最多 3 次）
    │
    └──→ [PostProcessAgent] 格式转换/纹理优化
            │
            ▼
            最终模型存入 MinIO
            元数据存入 MySQL
            模型特征 Embedding 存入 Milvus
            │
            ▼
[WebSocket] 推送完成通知到前端
    │
    ▼
[前端] Three.js 加载并展示 3D 模型
```

#### 6.2.3 详细功能说明

**M1-F1 用户注册**

- **前置条件**：用户未登录，访问注册页面
- **输入**：邮箱地址、密码（8-20 位，包含大小写字母和数字）、确认密码、验证码
- **处理流程**：
  1. 前端校验输入格式（邮箱格式、密码强度、密码一致性）
  2. 后端校验邮箱是否已注册
  3. 密码使用 bcrypt 算法哈希存储
  4. 生成用户记录，分配默认免费额度（每月 5 次生成）
  5. 发送欢迎邮件（可选）
- **输出**：注册成功，自动登录并跳转到首页
- **异常处理**：
  - 邮箱已注册：提示「该邮箱已注册，请直接登录」
  - 验证码错误：提示「验证码错误，请重新输入」

**M1-F2 用户登录**

- **前置条件**：用户已注册
- **输入**：邮箱 + 密码，或第三方登录授权
- **处理流程**：
  1. 前端校验输入非空
  2. 后端校验邮箱存在性和密码正确性
  3. 生成 JWT Access Token（有效期 24h）和 Refresh Token（有效期 7 天）
  4. 记录登录日志（IP、时间、设备）
- **输出**：登录成功，返回 Token，前端存储到 localStorage
- **异常处理**：
  - 邮箱不存在：提示「该邮箱未注册」
  - 密码错误：提示「密码错误，剩余尝试次数：X」（最多 5 次，之后锁定 30 分钟）
  - Token 过期：自动使用 Refresh Token 刷新，刷新失败则跳转登录页

**M1-F3 身份认证**

- **认证机制**：基于 JWT 的无状态认证
- **Token 结构**：

  ```json
    "sub": "user_id",

  }
  ```

### 6.5 模块 M4：RAG 知识检索

#### 6.5.1 功能概述

| M4-F2 | 参数向量检索 | 基于角色特征检索最优生成参数 | P0 | 参数推荐采纳率 >= 70% |
| M4-F3 | 材质向量检索 | 基于角色特征检索匹配的材质参考 | P1 | 材质匹配满意度 >= 75% |
| M4-F4 | 检索结果融合 | 多路检索结果融合与重排序 | P0 | 融合结果相关性 >= 85% |

| M4-F6 | 检索反馈优化 | 用户可对检索结果进行反馈，优化 RAG | P1 | 反馈后检索准确率提升 >= 5% |

#### 6.5.3 详细功能说明

**M4-F1 风格向量检索**

- **输入**：角色特征文本（由 M3 模块输出转换而来）
- **处理流程**：
  1. 将角色特征 JSON 转换为自然语言描述文本
  2. 使用 text-embedding-3-large 生成 1024 维向量
  3. 在 Milvus `character_style_collection` 中执行 ANN 搜索
  4. 返回 Top-5 相似风格记录
- **输出**：相似风格列表（含风格名、标签、推荐参数、相似度分数）

**M4-F2 参数向量检索**

- **输入**：角色特征向量 + 任务类型（anime_character / object_model）
- **处理流程**：
  1. 根据任务类型过滤 `generation_params_collection`
  2. 执行向量相似度搜索，返回 Top-3 最优参数记录
  3. 按成功率和平均质量评分排序
- **输出**：最优参数组合（含 guidance_scale、steps、mesh_simplification 等）

**M4-F4 检索结果融合**

融合策略：

```
输入：style_results(风格检索), param_results(参数检索), material_results(材质检索)

融合步骤：
1. 归一化：将各路检索的相似度分数归一化到 [0, 1]
2. 加权融合：final_score = 0.4 * style_score + 0.4 * param_score + 0.2 * material_score
3. 去重：相同参数组合去重，保留得分最高者
4. 重排序：按 final_score 降序排列
5. 截断：取 Top-3 作为最终推荐

输出：融合后的推荐参数配置
```

**M4-F5 参数自动推荐**

| topology_type | 用户选择 | triangle | 游戏用途推荐 quad，打印推荐 triangle |

**M6-F6 自动重试机制**

重试策略：

```
首次生成 → 质量评估
    │
    ├──→ 全部通过 (score >= 0.8) → 进入后处理
    │
    └──→ 部分不通过 (score < 0.8)
            │
            ├──→ 第 1 次重试
            │   ├──→ 水密性不通过: 增加 mesh_simplification 阈值 -0.1
            │   ├──→ 面数过高: 降低 mesh_density 一档
            │   ├──→ 面数过低: 提高 mesh_density 一档
            │   └──→ 纹理质量低: 提高 texture_resolution 一档
            │   → 重新生成 → 质量评估
            │
            ├──→ 第 2 次重试（如第 1 次仍不通过）
            │   ├──→ 综合调整多个参数
            │   └──→ 切换引擎（TRELLIS-2 ↔ TripoSR）
            │   → 重新生成 → 质量评估
            │
            └──→ 第 3 次重试（如第 2 次仍不通过）
                    ├──→ 使用最保守参数组合
                    └──→ 如仍不通过，标记为失败，通知用户
```

```
  │     │     ├──→ 填写邮箱、密码、确认密码
  │     │     ├──→ 获取并输入验证码
  │     │     ├──→ 前端格式校验
  │     │     ├──→ 提交注册请求
  │     │     ├──→ 后端校验（邮箱唯一性、密码强度）
  │     │     ├──→ 密码哈希存储
  │     │     ├──→ 生成用户记录
  │     │     ├──→ 分配免费额度
  │     │     ├──→ 生成 JWT Token
  │     │     └──→ 返回 Token，自动登录
  │     │
  │     └──→ 点击「登录」
  │           ├──→ 输入邮箱和密码
  │           ├──→ 提交登录请求
  │           ├──→ 后端校验（邮箱存在性、密码正确性）
  │           ├──→ 生成 JWT Token（Access + Refresh）
  │           ├──→ 记录登录日志
  │           └──→ 返回 Token
  │
  └──→ 已登录用户
        ├──→ 验证 Token 有效性
        ├──→ Token 有效 → 正常访问
        └──→ Token 过期 → 自动刷新 → 刷新失败 → 跳转登录
```

#### 7.2.2 图片上传与预处理流程

```
用户执行上传操作
  │
  ├──→ 拖拽/点击/粘贴/URL
  │
  ▼
前端接收文件
  ├──→ 文件类型初步校验（MIME type）
  ├──→ 文件大小初步校验（<= 20MB）
  ├──→ 显示上传进度条
  └──→ 分片上传（大文件）或直接上传
  │
  ▼
后端接收并处理
  ├──→ 格式深度校验（文件头魔数）
  ├──→ 尺寸检测（读取图片元数据）
  ├──→ 质量检测（清晰度、主体占比、多人检测）
  ├──→ 自动预处理
  │     ├──→ 格式统一转 PNG
  │     ├──→ 尺寸归一化
  │     ├──→ 质量优化
  │     └──→ EXIF 清理
  ├──→ 可选：背景移除（AI 分割）
  ├──→ 存入 MinIO
  └──→ 返回图片 URL 和预处理报告
  │
  ▼
前端展示预览和参数配置面板
```

#### 7.2.3 3D 生成任务调度流程

```
用户提交生成任务
  │
  ▼
后端接收请求
  ├──→ 校验用户权限和剩余额度
  ├──→ 创建项目记录（如为新项目）
  ├──→ 创建生成任务记录（status: pending）
  ├──→ 生成唯一 task_id
  └──→ 提交 Celery 异步任务
  │
  ▼
Celery 任务队列
  ├──→ 任务进入 Redis 队列
  ├──→ Worker 消费任务
  ├──→ 更新任务状态为 processing
  ├──→ 启动 LangGraph 工作流
  └──→ 执行各智能体节点
  │
  ▼
任务状态管理
  ├──→ 每个状态变更写入 Redis
  ├──→ WebSocket 推送状态到前端
  ├──→ 前端实时更新进度条和日志
  └──→ 任务完成/失败后更新 MySQL
  │
  ▼
结果处理
  ├──→ 成功：模型存入 MinIO，更新任务状态为 completed
  ├──→ 失败：记录错误信息，更新任务状态为 failed
  └──→ 通知用户（WebSocket + 可选邮件）
```

### 9.3 数据流说明

```
用户上传图片
  │

  │
  ├──→ 创建 project 记录 → MySQL
  │

  │
  ├──→ 提交 Celery 任务 → Redis
  │
  ├──→ 角色分析结果 → MySQL（character_features 表）
  │     └──→ 特征 Embedding → Milvus
  │
  ├──→ RAG 检索结果 → MySQL（generation_task.retrieved_params）
  │
  ├──→ 生成参数 → MySQL（generation_task.generation_params）
  │
  ├──→ 3D 模型文件 → MinIO
  │
  ├──→ 纹理贴图文件 → MinIO
  │
  ├──→ 模型元数据 → MySQL（model_metadata 表）
  │
  ├──→ 模型特征 Embedding → Milvus（用于后续检索）
  │
  └──→ 更新任务状态 → MySQL（status: completed）
        └──→ 更新 RAG 知识库统计 → MySQL
```

```
  │
  └──→ 用户反馈 → 更新知识条目统计 → MySQL
        └──→ 影响后续检索排序权重
```

### 13.4 风险矩阵

```
                    高影响
                       ↑
    ┌──────────────────┼──────────────────┐
    │  R-T3 GPU成本    │  R-B1 竞品跟进   │
    │  R-B4 付费意愿   │  R-B5 大厂入局   │
    │  R-O1 冷启动     │  R-T1 生成质量   │
    │                  │  R-T2 识别准确率 │
低概率←────────────────┼────────────────→高概率
    │  R-T7 许可证冲突 │  R-B6 技术迭代   │
    │  R-B3 市场规模   │  R-T6 WebSocket  │
    │  R-T4 Milvus性能 │  R-O2 留存率低   │
    │                  │  R-O3 恶意刷量   │
    └──────────────────┼──────────────────┘
                       ↓
                    低影响
```

**应对优先级**：
1. **高影响 + 高概率**：R-B1（竞品跟进）、R-B5（大厂入局）、R-T3（GPU 成本）→ 立即制定详细应对计划
2. **高影响 + 中概率**：R-T1（生成质量）、R-T2（识别准确率）、R-B4（付费意愿）、R-O1（冷启动）→ 纳入迭代规划
3. **中影响 + 中概率**：R-T5（模型加载）、R-T6（WebSocket）、R-B6（技术迭代）、R-O2（留存率）→ 持续监控
4. **低影响 + 低概率**：R-T7（许可证）、R-T4（Milvus）→ 定期审查
