# 抠图部件缺失与生成拦截修复 · 2026-10-21

## 原因与修复

建筑编辑器截图中的细长宝顶会被全图 U2Net 分割遗漏。此前框选只在分割后裁剪，实际分割仍读取整张编辑器截图，工具栏和网格继续影响结果。现在 `/studio/images/remove-background` 支持百分比 `crop`，服务端先按 EXIF 校正后裁剪、再送本机分割，最后把透明结果放回原图坐标。前端不再出现裁剪与遮罩坐标漂移。自动识别在尚未手动框选且置信度至少 0.75 时，使用带 3% 余量的建议范围；已有手动框选优先。

新增「修补抠图」：恢复遗漏部件、擦除多余背景、调节笔宽、撤销上一步、原图定位底图、取消和保存。恢复直接复制原图 RGBA，不重绘或虚构细节。定位层只用于显示，不混入导出的透明 PNG。保存时扩大裁剪范围以包含修补后可见部件，避免刚恢复的部件再次被裁掉。重新自动抠图会覆盖手工修补。

完整性复核失败或不确定时，增加「我已对照原图检查，接受当前抠图结果并继续」。人工确认单独记录，不把 AI 的 fail/uncertain 改写成 pass。重新处理、修改图片或重新复核会清除人工确认。

「不抠图，使用原图」允许保留完整原图。复杂背景时先显示明确提示，用户选择「接受背景风险，使用原图」后生成入口解锁。`background_risk_accepted: true` 随预处理记录传入任务、后台图像校验和引擎；只接受布尔 true。没有明确选择时，复杂背景仍默认拦截，防止无意中生成背景板。后台记录实际图片 SHA256、实际背景类型和风险确认状态；不信任客户端“已抠图”的自报值。

## 验证与边界

- 后端相关测试 36 项通过：裁剪先于分割、透明遮罩回贴原坐标、无效裁剪不调用模型、复杂背景默认拒绝、明确确认后用同一输入入队并传到引擎。
- 引擎测试 22 项通过：明确接受背景后保留原图像素；未接受仍拒绝已知复杂背景；原有透明 PNG 合黑底、构图和工作流参数行为保持。
- 前端图像测试 5 项通过，生产构建通过：恢复细长部件的原始 RGBA、连续笔迹不留空洞、擦除不改动剩余 RGB、原有构图与锐化检查。
- 使用项目实际的 `d1fe26b02bba6d4fbeed87c2becbb1a8.jpeg`（1920×1080），真实调用本机分割：整图分割丢失宝顶；框选 x=7%、y=10.5%、width=68%、height=81.5% 后宝顶保留。对照位于 `tmp/foreground-repair-20261021/pavilion-full-view.jpg` 与 `pavilion-cropped-view.jpg`。
- 浏览器实测原图风险确认后可解锁生成；修补画笔、撤销、取消定位层、保存及人工确认解锁均有效。识别、分割与双图复核实际运行。自动裁剪保留了建筑主体，但可能保留顶部悬浮工具栏，仍需修补或更精细的手动框选，不能宣称自动抠图对所有图片都准确。
- 最终浏览器实测：对实际原图运行自动抠图后，用擦除画笔清理悬浮工具栏，保存，再次调用 DeepSeek 双图复核，真实返回 pass，说明塔尖、三层飞檐、牌匾、栏杆、柱子和底座均保留且无界面残留。点击「确认此图用于生成」后显示「生成输入已确认」，生成按钮可用。证据：`tmp/foreground-repair-20261021/ui-repaired-ready.png`；原图确认路径证据：`ui-original-ready.png`。

本轮验证预处理、确认、任务接口和引擎输入契约，没有重新运行完整 GPU 图生 3D。自动复核用于辅助检查，不是部件完整性的保证；原图直接生成也不能保证背景不进入几何。

## 使用

1. 刷新到最新页面并重新选图，先点击「自动抠图」。建筑/物品可在高级调整中先框选完整主体，再点击同一按钮。
2. 部件缺失或有界面残留时点击「修补抠图」，用恢复/擦除画笔处理，保存后重新检查或人工确认。
3. 需要完整保留原图时，点击「不抠图，使用原图」，接受页面列出的背景风险，再点击生成。

服务已更新到本地前端 8080、API 8002；生成服务按本机现有 ComfyUI 配置运行。
