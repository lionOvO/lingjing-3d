# 生成背景板与引擎质量差异修复 · 2026-10-21

## 问题与已确认的原因

任务 #30 使用 658×1395 的精灵角色参考图。其预处理记录为 version=2、background_removed=false、background_kind=complex。页面仅把整张图片缩入 1024 方形画布，实际送入 ComfyUI 的图仍包含暗色背景矩形。服务因为 input_preprocessed=true 跳过了原有分离前景步骤；“整理过构图”被误当成“已经分离前景”。背景板是输入链路问题，不能靠检查与修复页删除重复面解决。

独立成功工作流是 docs/Pixal3D_第五轮_完整生成_1024_API.json，平台工作流为 services/trellis/workflow_6gb.json。核对模型节点 39 与生成节点 45，修正后模板参数相同。节点 54 仅有目标面数 500001 与 500000 的差异。本次旧任务的形状 16 步、纹理 20 步本来就与独立工作流一致，不能把这次质量问题归咎于采样步数降低。

其他实际差异：旧平台给每次提交生成随机种子，没有保存实际种子；全图留白导致人物像素占比偏小；旧通用分割模型在本图中漏掉双臂与衣袖。

## 修正后的输入契约

- 前端先展示原始参考图与真正导出的生成输入。左侧始终是原始文件，避免处理结果自我对照掩盖缺失。
- 简单背景允许保留；复杂背景需分离前景并人工确认双臂、衣袖与配饰，不能直接确认原图。
- 后端读取实际上传字节及原图，重新检查背景类型，不信任 background_removed 等客户端声明。复杂原图外加纯色边框也不能绕过检查；失败时返回 422，不入 GPU 队列。
- 动漫角色可选 ISNet Anime，通用图可选 U2Net，不自动回退到另一模型。默认本机 CPU 运行、子进程退出后释放内存，推理时不下载权重。
- Anime 分割置信度转换为前景遮罩，避免把低置信度衣袖当成半透明衣物。保留原图 RGB，12 以下清除、32 以上作为前景，中间范围保留软边。这个阈值是本轮已验证配置，不代表所有图片均无需检查。
- 有透明轮廓时，白底/灰底只改变页面预览，下载和生成均保留透明 PNG。服务按原引擎方式合成黑底 RGB，不再二次抠图、裁剪或改变尺寸。
- 默认人物留白由 8% 改为 2.5%，在透明轮廓范围内等比居中。默认不锐化、不重绘，不补全未见部位。
- 已有任务的输入记录提供“用原始参考图重新生成”，避免把旧的缩小图片反复当原图处理。

## 参数一致与复现

默认种子 109020838 对齐独立第五轮工作流；页面可填 0–2147483647 的整数。显式种子通过 API、worker 送入节点 45，保存在任务、预设和复用参数中。导出文件名仍保持唯一，但不再影响种子。低/中/高面数只控制导出目标面数，不再暗改采样步数。

复现须保持原始输入、确认后的实际输入、种子、工作流及模型版本一致。仅同种子不能保证不同图片或不同运行环境得到逐字节相同的模型。

## 能力边界

当前没有添加语义视觉模型，也没有使用 AI 重绘参考图。像素检查不判断人物数量、遮挡或肢体语义完整性；分割模型也可能误判细配饰或本来透明的材质。本轮实测可证明这张参考图的输入与链路修复，不能保证任意参考图均达到相同质量。单张图片看不到的背面细节仍由 3D 生成模型推断。
