# 生成内存修复（2026-10-22）

## 修改范围

针对原失败任务 36（项目 31）在 NAF CPU 拷贝时的系统提交内存耗尽，修改本机 ComfyUI-Trellis2-GGUF 的通用生成路径。模型权重、1024 cascade 分辨率、NAF 精度、采样步数、面数及纹理规格没有降低。

### 临时特征缓冲区

Windows FP32 特征的 GPU → CPU 拷贝改为 NumPy 持有底层内存、PyTorch 视图执行同步拷贝。大块 CPU 特征拼接也使用相同的内存所有权方式。其他系统、非 FP32 数据保持原路径。

隔离实验中，原 torch CPU 分配方式每轮删除后仍增加约 264.5 MiB 私有提交占用；新方式在预热后连续多轮保持稳定，GPU allocated/reserved 在清理后均为 0。缓冲区切片保有底层所有者，避免提前释放；不会转换精度或改写特征值。

涉及引擎文件：

- `trellis2_gguf/utils/host_buffers.py`
- `trellis2_gguf/trainers/flow_matching/mixins/image_conditioned_proj.py`
- `trellis2_gguf/pipelines/trellis2_image_to_3d.py`

32 MiB 以上的大块暂存会记录当前系统提交量；不足以容纳目标数据并留出 256 MiB 余量时，抛出可处理的 MemoryError，而不是继续触发 native 分配失败。

### 阶段生命周期

- `keep_models_loaded=false` 时，LR 采样结束立即移除已完成的 LR flow 模型，跳过原先额外的 `.cpu()` 权重副本；保留模型的模式仍执行原卸载逻辑。
- LR 条件和噪声用完即释放，不再为无后续消费者的 LR 条件做 CPU 拷贝。
- upsample 结束释放 LR latent；重建 HR 条件前释放被替代的旧条件。
- 1024 cascade 的调用者转移条件所有权，避免外层 `run()` 继续保留已完成阶段的数据。
- 纹理条件模型推迟到纹理阶段加载，避免在 LR、HR 形状阶段无用地占据系统内存。

加载顺序发生变化，因此不承诺新旧整个模型文件逐字节一致；所有权调整的小张量对照测试保持相同输入、随机种子和采样参数，级联采样输出数值完全一致。

### 引擎断开时的提示

`services/trellis/app.py` 区分 ConnectError 和 RemoteProtocolError，明确说明引擎连接失败或生成期间连接中断，提示检查引擎日志及系统提交内存。现有后端收到服务的明确失败响应后不重新提交 GPU 任务，本地部署 `GENERATION_SERVICE_RETRIES=0`。
