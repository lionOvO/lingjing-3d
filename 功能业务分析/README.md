# 功能业务分析

基于工作区根目录的产品 PRD 与当前前后端源码，按 PRD 的 **13 个模块** 顺序组织；**75 个 PRD 功能 + 16 个源码补充功能 = 91 份独立功能文档**。每份文档恰含一张业务流程图和一张时序图，共 182 张 Mermaid 图。

## 阅读与范围

- 以 PRD“详细功能清单”为覆盖依据，保留 Mx-Fy 标识；模块总览的数量不一致时以详细清单为准，未将模块数强行限制为 7。
- 分析对象为根目录 frontend、backend、services 及实际调用的 models/triposr；未混用 3d-toolchain 或 submission_staging 代码副本。
- 已实现、部分实现、仅后端 API 与未实现需求分别标明。未实现功能提供完整设计图；部分实现图中的 [设计]、虚线与设计分支明确区分需求补充。
- 源码补充功能追加到原模块末尾；不改动 PRD 已有功能编号。
- 纯前端交互注明无需后端保存；3D 预览相关文档包含前置模型获取链路。
- 图按任务成功、失败、降级、重试和异步回写路径表达。U/F/V/B/A/W 等缩写在每份文档单独解释。
- 分析为静态源码核对，未声称 PRD 性能、准确率、服务可用性或业务运行已验收。
- 源码链接定位到本工作区绝对路径与行号；模块与功能间使用相对链接，方便目录整体搬移。

## 必须按真实边界理解的链路

当前转换接口只修改 output_format；知识库页面是关系库关键词匹配；Agent 检索才使用 Milvus；前端不保存 refresh_token；多数业务路由未普遍挂载当前用户依赖；取消任务不保证终止正在运行的推理。质量判据存在模式差异与弱检查，详见相关独立功能文档。
